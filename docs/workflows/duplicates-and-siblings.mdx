Data Leads use **Students → Duplicates** (`/admin/duplicates`) to resolve potential duplicate records. Each pair shows **home addresses** and how they compare.

## Who can access

**Admin** and **Data Lead** only.

## How intake surfaces matches

During **NEW** registration, Intake checks in two stages:

1. **Check ASISTS first** — search by name, DOB (MM/DD/YYYY or YYYY-MM-DD), or both. A DOB-only search returns only students born that day.
2. **After unlock** — when personal info is filled, the system re-checks **same DOB** (always shown for sibling review), **similar name** (match %), and **home address**.

Staff can:

- Use **Same person sitting here — log returning** when the match is the student at the desk
- Check **Not the same person sitting here** (ASISTS gate) or **This is a different person with the same name** (duplicate panel) to flag siblings for Data Lead review
- Notify the Data Lead with **Copy alert message** (Teams / Slack / paste into email) or **Email with alert** (opens mail with subject + body filled in)

Each match card shows a **% match** (name similarity) and a **Same DOB** badge when birthdays align.

## Intake alert message

The copied alert is written for Data Lead review. It includes:

- A clear **Subject** line (`Possible duplicate student — Intake alert`)
- School, who reported it, and when
- The NEW student being registered (name, DOB, phone, email, address — shows **—** if a field is still blank)
- Possible matches in this system and on ASISTS / legacy (DOB, Label ID, status, similarity, same-DOB / address notes)
- Short **What to do** steps and a link to `/admin/duplicates`

If intake already checked **different person**, the intro line says the registration was flagged as a sibling / coincidence path.

<Note>
  **ASISTS gate:** after a name or DOB search, confirm **Same person sitting here — log returning**, or check **Not the same person sitting here** to unlock NEW intake (flagged for Data Lead review).
</Note>

## Flagged section

Students marked by Intake Members with **This is a different person** appear here for review.

Intake may flag a pair when names and DOB are similar but the student insists they are a different person — often siblings.

## Auto-detected section

The system scans students for:

- **Same DOB + similar name** (fuzzy match, including middle-name omissions), **or**
- **Same DOB + same home address** (even when names do not fuzzy-match)

On Intake, **all same-DOB** students also appear for review (with match %), so siblings with different first names are not dropped when staff type a new name.

Pairs already confirmed as siblings, manually dismissed, or still flagged in the first section are excluded.

## Address comparison

Between each pair, a comparison block shows:

| Badge | Meaning |
| --- | --- |
| **Same verified address** | NYC-standardized data matches |
| **Same address** | Street, apt, city, and ZIP align |
| **Same building** | Same building, different unit — likely siblings |
| **Different address** | Different homes — sibling at new address or possible move |

<Tip>
  **Matched by address** appears when the pair was surfaced primarily by home address, not name similarity.
</Tip>

Each student card also shows their formatted address (street + apt on one line, city/state/ZIP below) and a **Verified** badge when NYC Geoclient confirmed the record.

## Actions

| Action | Result |
| --- | --- |
| **Confirm Siblings** | Links both records bidirectionally; sibling badge appears on student pages |
| **Merge Records** | Choose which record to keep, then pick which fields to keep (email, phone, program, notes, address group, etc.); secondary is deleted; **Undo** ~10 seconds |
| **Dismiss / Not a duplicate** | Hides the pair permanently |

### Merge field review

When you click **Merge Records**:

1. Select the **primary** student (the record that remains)
2. Review the **field diff** — each row shows Same / Conflict / Only primary / Only secondary
3. Click a value to keep it (defaults: primary wins on conflicts; secondary fills empties)
4. **Home address** is chosen as one group (street, apt, city, ZIP + verification)
5. Confirm — secondary is deleted and its drawer slot is freed

Use **All primary** or **Prefer secondary fills** for quick defaults, then adjust conflicts after verifying with the student.

<Warning>
  **Merge** deletes the non-primary record and frees its drawer slot. A snackbar offers **Undo** for about 10 seconds — after that the delete is final. Verify conflicting fields before confirming.
</Warning>
